# Tonia-SoundGate 声音闸门

> 摸鱼防泄露 · 常驻后台的静音守护程序

一个极简的 Windows 托盘程序：**默认强制静音**，一旦检测到系统被解除静音（开会、误触、其他程序外放），立刻重新静音并弹出授权提示。你可以选择授权时长，时长内不再打扰；到期自动恢复静音。让你不再因为"事后忘记开静音"而泄露声音。

## 核心机制（强预防式）

- **守护态**：程序运行时系统始终保持静音。任何外部解除静音都会被立即拦截。
- **授权态**：在弹窗点"允许外放"、或在托盘面板授权并通过二次确认后，进入带到期时间的放行窗口。
- **到期强制回归**：授权到期自动静音，回到守护态——不依赖你的记忆。
- **双层保障**：WASAPI 静音事件监听 + 200ms 高频巡检兜底，设备热插拔自动重新绑定。实测发现部分蓝牙设备的 WASAPI 通知回调延迟可达 1~2 秒，此时**巡检才是真正第一道防线**，故把巡检间隔压到 200ms；事件与巡检互为补充，任一先到即拦截。

这解决了纯"检测播放再拦截"方案的竞争窗口问题，也解决了"开会解除静音后忘记恢复"的泄露风险——因为系统永远会替你把关。

## 功能

- 系统托盘常驻，两种状态图标：红色（守护中）、绿色（授权中，带剩余时间倒计时）
- 检测到解除静音 → 弹窗询问，可选时长：30 分钟 / 1 小时 / 4 小时 / 1 天（默认）/ 自定义分钟数
- 弹窗 30 秒无操作自动按"保持静音"处理，避免长期滞留
- **解除静音一律二次确认（防误触）**：
  - 双击托盘图标**只打开面板**，不会授权（v1.0.1 修复：此前双击即授权，误触一次声音就外放了）
  - 面板里点「立即授权 N…」后，还要在独立确认框里点「确认解除」才生效
  - 确认框默认焦点在「保持静音」，Enter / Esc 也都走安全侧；「确认解除」延迟 700ms 才可点击，防止连点穿透；20 秒无操作自动保持静音
  - 拦截弹窗的默认按钮同样是「保持静音」，键盘误敲不会外放
- **Windows 11 设置风格界面**：弹窗与托盘面板均为浅色圆角卡片，统一配色与图标；弹窗分区布局、留白充足，长设备名自动省略，杜绝文字拥挤裁切
- **自绘托盘面板**：替代系统自带菜单，含状态实时倒计时、逐项图标、hover 高亮；点击外部或 Esc 关闭
- 托盘面板：授权外放 30 分钟/1 小时/1 天、立即恢复守护、开机自启（带勾选）、退出
- 记住上次授权时长；单实例保护；配置存于 `%AppData%\Tonia-SoundGate\settings.json`

## 安装包（推荐给最终用户）

已生成的可分发安装包：

```
packaging\dist\Tonia-SoundGate-Setup-1.0.1.exe     # 约 58 MB
```

> `packaging\dist` 与 `packaging\publish` 都在 `.gitignore` 里，不进版本库（单文件 60 MB 以上），需要按下方「重新打包」在本地生成。

安装包特性：

- **自包含发布**：内置 .NET 8 桌面运行时，目标机器**无需预装 .NET**，双击安装即可用
- 装到 `C:\Program Files\Tonia-SoundGate`，需一次 UAC 提权；安装前会自动结束正在运行的旧实例
- 创建开始菜单快捷方式（含卸载入口），另可选桌面快捷方式
- 注册到「设置 → 应用 / 程序和功能」，支持标准卸载
- 卸载时询问是否一并删除个人配置（`%AppData%\Tonia-SoundGate`），并清理开机自启的注册表项
- 安装末尾可勾选「立即启动」；**启动后会立即强制静音**，正在外放需右键托盘临时授权

### 重新打包

```bash
# 1) 自包含单文件发布（输出到 packaging\publish，该目录不进版本库）
dotnet publish -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=none \
  -o packaging\publish

# 2) 用 NSIS 3 编译安装脚本（makensis 以脚本目录为工作目录，故需 cd 进去）
cd packaging && makensis /INPUTCHARSET UTF8 setup.nsi
```

图标源文件为 `packaging\app.ico`（多尺寸 16~256px，程序化绘制，无外部素材依赖），项目根目录的 `app.ico` 已通过 `ApplicationIcon` 嵌入 exe。

## 构建与运行

需要 .NET 8 SDK（Windows）。

```bash
dotnet build -c Release
# 生成物：bin/Release/net8.0-windows/Tonia-SoundGate.exe
```

直接双击 exe 运行即可，程序会常驻系统托盘。若需开机自启，在托盘右键菜单勾选"开机自启"（写入当前用户的注册表 Run 键，无需管理员权限）。

## 技术栈

- .NET 8 / WinForms（无主窗口，`ApplicationContext` + `NotifyIcon`）
- NAudio 2.2.1（`AudioEndpointVolume.Mute` + `OnVolumeNotification` 事件，WASAPI 底层）
- UI 全程序化绘制：托盘图标、圆角卡片、圆角按钮、面板图标均无外部图片/CDN 依赖
- DWM 窗口圆角（Win11 原生，Win10 回退到 Region 圆角）+ 窗口阴影

## 实测验证（2026-11-16）

在真实桌面会话（默认设备为 QCY 蓝牙耳机）做了端到端测试，四环节全部通过：

| 环节 | 方法 | 结果 |
|---|---|---|
| 启动强制静音 | 启动后读系统静音状态 | 通过，启动即从"未静音"切为"静音" |
| 外部解除静音被拦截 | 独立进程主动解除静音并高频采样 | 通过，状态被自动按回静音 |
| 授权弹窗弹出 | 触发拦截后截取桌面 | 通过，弹窗、时长选项、双按钮均正常显示 |
| 授权后放行 | 点击弹窗「允许外放」后观察 | 通过，解除静音并进入授权态，巡检持续 `allow` 不再弹窗 |

测试中发现并修复的两个真实缺陷：
1. **自身事件误判**：NAudio 通知是异步回调，原先用"调用栈标志"判断自身操作，回调到达时标志已失效，导致自身静音被误判为外部解除而反复拦截。改为"期望值 + 时间窗"比对后修复。
2. **设备热插拔检测失效**：原 `DeviceName` 返回缓存设备名，永远检测不到切换；改为按设备 ID 重新枚举并真正调用 `RebindDevice()`。

### UI 优化与实测（同日续）

按 Windows 11 设置风格重做了弹窗与托盘面板，并在 175% DPI 缩放的真实桌面上逐项截图核验：

- **弹窗**：改为浅色圆角卡片、分区布局（标题 / 警告卡 / 时长选择 / 底栏）。修掉了原版在高 DPI 下文字被裁切的问题——根因是固定像素尺寸装不下放大后的字体，通过加大控件尺寸与留白解决（"保持静音"不再被裁成"保持静"、"自定义"、设备名、时长标题均完整）。
- **托盘面板**：用自绘无边框窗体替换系统 `ContextMenuStrip`，圆角卡片 + 状态实时倒计时 + 逐项图标 + hover 高亮。修掉了自绘菜单项用 `Color.Transparent` 导致的**"控件不支持透明的背景色"崩溃**（普通 Control 子类不支持透明背景，改用与父容器一致的纯色）。

排障用的诊断日志保留在 `DebugLog.cs`，默认关闭（`Enabled = false`）；排查时改为 `true` 重新编译，日志写到程序目录 `soundgate.log`。

### 交互反馈优化（同日续二）

针对"数字框裁切、菜单点击迟滞、启动无反馈"三个体验问题做了改造：

- **自定义数字框**：系统 `NumericUpDown` 在高 DPI 下高度不随 `Size` 变化，内部文本与上下箭头会按错误比例裁切，且无法通过属性修正。改为自绘控件 `NumberInput.cs`（圆角边框 + 内嵌无边框 TextBox + 自绘上下箭头），高度按控件尺寸自适应，数字与箭头都能完整显示。
- **点击迟滞**：原托盘菜单是"先执行动作、后关闭面板"，而授权/恢复守护会走 WASAPI COM（蓝牙设备可达数百毫秒），导致面板卡住后才消失。改为**先 `Close()` 再执行动作**，面板立即消失；菜单行同时增加按下态反馈。
- **操作反馈**：新增右下角 Toast 通知（`ToastForm.cs` + `ToastService.cs`），圆角卡片、左侧强调色条、淡入淡出、不抢焦点、单条替换不堆叠。授权 / 恢复守护 / 开机自启 / 弹窗授权都会给出明确结果提示。
- **启动反馈**：纯托盘应用启动时不再"只多一个陌生图标"，而是延迟 600ms 弹出"已启动 · 静音守护中 · 右键托盘图标可授权或退出"；重复启动时，已运行实例会提示"程序已在后台运行"（通过命名 `EventWaitHandle` 通知）。

### 防误触二次确认（v1.0.1）

用户反馈的严重缺陷：**双击托盘图标会直接解除静音**，极易误触导致声音外放。排查出三处"一次点击即放行"的入口，全部改为安全侧：

| 入口 | 原行为 | 修复后 |
|---|---|---|
| 双击托盘图标 | 立即按上次时长授权 | 只打开托盘面板，不做任何授权 |
| 面板「立即授权 30 分钟/1 小时/1 天」 | 单击即授权 | 弹独立确认框，确认后才生效（菜单文案加「…」提示还需一步） |
| 拦截弹窗的 Enter | 默认按钮是「允许外放」，误敲键盘即外放 | 默认按钮改为「保持静音」，Enter/Esc 都走安全侧 |

新增 `ConfirmForm.cs` 作为统一的二次确认框，安全侧设计四条：

1. 默认焦点在「保持静音」，`AcceptButton` / `CancelButton` 都指向它——键盘怎么误触都不会外放；
2. 「确认解除」按钮**延迟 700ms 才可点击**，防止用户在面板上连点时穿透到确认框；
3. 20 秒无操作自动按「保持静音」关闭，框被晾着也不会留下未决状态；
4. 居中弹出而非贴着鼠标弹出，鼠标必须主动移动过去。
5. 拦截弹窗的「允许外放」同样延迟 700ms 启用，避免"连点穿透"。

本轮无裁切问题：确认框按两行正文排版（文案内显式换行 + 容器高度 64），在 175% DPI 下用 1:1 导出图核验标题、红字警告、两行正文、倒计时提示、双按钮均完整；同时核验了按钮禁用态（灰底灰字）与启用态（强调蓝）的视觉区分。

## 已知边界

- 仅监听"默认播放设备"（Console 角色）；多设备同时外放的场景不在首版范围
- 授权期内切换播放设备会回到守护态重新把关（安全优先）
- 首次启动会立即静音；如你正在外放请先做好预期
- 蓝牙设备存在固有的音频栈延迟，实测拦截窗口约 0.7 秒（含 COM 往返与设备延迟）；对有线设备通常更快
